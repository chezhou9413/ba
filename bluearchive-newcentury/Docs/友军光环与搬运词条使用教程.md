# 友军光环与搬运词条使用教程

适用版本：RimWorld 1.6。XML 文件使用 UTF-8 编码。

## 1. 定义名称

| defName | 用途 |
| --- | --- |
| `BANW_LogisticsAura` | 给角色添加的后勤光环源状态 |
| `BANW_LogisticsAuraEffect` | 地图自动施加、维护和移除的后勤受益状态 |
| `BANW_HaulingCapacityMultiplier` | 单次搬运容量倍率，默认 1 |
| `BANW_CarryMassOffset` | 额外质量负重，单位 kg，默认 0 |
| `BANW_CarryMassMultiplier` | 质量负重倍率，默认 1 |

光环定义位于 `1.6/Defs/Auras/FriendlyAuras.xml`，搬运属性位于 `1.6/Defs/Carrying/CarryingStats.xml`。光环需通过技能或其他添加状态的方式赋予角色。

给一个角色添加 `BANW_LogisticsAura` 后，8 格内自身、同阵营角色和盟友会获得后勤支援：单次搬运容量 +50%，质量负重先 +15 kg 再 ×1.25。该示例允许动物和机械体受益，但不赋予原本没有的工作能力。

## 2. 给技能添加光环

把下面组件合入现有 `AbilityDef/comps`，技能发动后为施法者添加光环源。不要直接施加 `BANW_LogisticsAuraEffect`。

```xml
<li Class="CompProperties_AbilityGiveHediff">
  <hediffDef>BANW_LogisticsAura</hediffDef>
  <onlyApplyToSelf>true</onlyApplyToSelf>
  <replaceExisting>true</replaceExisting>
</li>
```

示例源是永久状态，移除源状态便会停止发射。若需要限时光环，在源 `HediffDef/comps` 中与光环组件并列添加：

```xml
<li Class="HediffCompProperties_Disappears">
  <disappearsAfterTicks>1800</disappearsAfterTicks>
</li>
```

1800 tick 为 30 个游戏秒，受游戏速度和暂停影响。技能自身的给状态组件也可能设置持续时间，应以该技能的持续时间配置为准。

## 3. 自定义光环源：完整示例

以下是独立定义，可放入新的 `1.6/Defs/Auras/MyAuras.xml`。`defName` 不得与项目已有定义重复。

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <HediffDef>
    <defName>My_CommandAura</defName>
    <label>战地指挥光环</label>
    <description>征召且清醒时，为12格内可见的友军提供后勤支持。</description>
    <hediffClass>HediffWithComps</hediffClass>
    <isBad>false</isBad>
    <initialSeverity>1</initialSeverity>
    <comps>
      <li Class="BANWlLib.Auras.HediffCompProperties_FriendlyAura">
        <effectHediff>BANW_LogisticsAuraEffect</effectHediff>
        <radius>12</radius>
        <minimumRadius>0</minimumRadius>
        <severity>1</severity>
        <multiplyBySourceSeverity>false</multiplyBySourceSeverity>
        <minimumSourceSeverity>0.5</minimumSourceSeverity>
        <includeSelf>true</includeSelf>
        <affectSameFaction>true</affectSameFaction>
        <affectAllies>true</affectAllies>
        <affectNeutral>false</affectNeutral>
        <affectHumanlikes>true</affectHumanlikes>
        <affectAnimals>false</affectAnimals>
        <affectMechanoids>true</affectMechanoids>
        <affectDowned>true</affectDowned>
        <affectPrisoners>false</affectPrisoners>
        <affectSlaves>true</affectSlaves>
        <requireLineOfSight>true</requireLineOfSight>
        <requireSourceDrafted>true</requireSourceDrafted>
        <requireSourceAwake>true</requireSourceAwake>
        <allowSourceDowned>false</allowSourceDowned>
        <allowSourceMentalState>false</allowSourceMentalState>
        <allowTargetMentalState>false</allowTargetMentalState>
      </li>
    </comps>
  </HediffDef>
</Defs>
```

### 光环源全部参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `effectHediff` | 必填 | 受益状态；其类必须是 `BANWlLib.Auras.Hediff_FriendlyAuraEffect` |
| `radius` | 8 | 外半径，单位格，圆形范围，边界包含在内 |
| `minimumRadius` | 0 | 不受益的内圈半径，可配置环形区域；不得超过基础外半径 |
| `radiusMultiplierStat` | 不设置 | 源角色的倍率 StatDef；外半径 = radius × 该属性；内圈不乘倍率 |
| `severity` | 1 | 每个源提供的基础受益严重度，必须大于 0 |
| `multiplyBySourceSeverity` | false | 是否把受益严重度再乘光环源状态的当前严重度 |
| `severityMultiplierStat` | 不设置 | 再乘源角色该 StatDef 的值；负倍率按 0 处理 |
| `minimumSourceSeverity` | 0 | 源状态低于该严重度时停止发射 |
| `includeSelf` | true | 是否允许自身受益；自身仍受类型、倒地、内圈等过滤 |
| `affectSameFaction` | true | 允许同阵营角色；自身由 includeSelf 单独控制 |
| `affectAllies` | true | 允许外交关系为盟友的阵营 |
| `affectNeutral` | false | 允许外交关系为中立的阵营；敌对和无阵营他人始终排除 |
| `affectHumanlikes` | true | 允许类人角色 |
| `affectAnimals` | false | 允许动物 |
| `affectMechanoids` | true | 允许机械体；其他种族类别排除 |
| `affectDowned` | true | 允许倒地目标 |
| `affectPrisoners` | false | 允许囚犯；不会绕过阵营过滤，敌方囚犯仍不受益 |
| `affectSlaves` | true | 允许奴隶；仍须通过阵营等过滤 |
| `requireLineOfSight` | false | 要求源与目标格之间有原版视线 |
| `requireSourceDrafted` | false | 只有源角色征召时才发射 |
| `requireSourceAwake` | false | 只有源角色清醒时才发射 |
| `allowSourceDowned` | false | 倒地源是否继续发射；与清醒要求分别检查 |
| `allowSourceMentalState` | false | 精神状态异常的源是否继续发射 |
| `allowTargetMentalState` | false | 精神状态异常的目标是否可受益 |
| `requiredTargetHediffs` | 空 | 目标必须拥有列表中的每一个 HediffDef |
| `excludedTargetHediffs` | 空 | 目标拥有列表中任意 HediffDef 即排除 |

列表写法是 `<requiredTargetHediffs><li>已有状态的defName</li></requiredTargetHediffs>`；排除列表格式相同。只填写实际存在的定义，不要填写占位符。

倍率属性填写 StatDef 的 defName，例如 `<severityMultiplierStat>BANW_ExSkillMultiplier</severityMultiplierStat>`。属性值 1 表示不变，1.5 表示 150%。不要把百分数写成 150。

## 4. 自定义受益与同名叠加

不同源指向同一个受益 `defName` 时，每个目标只保留一个受益实例。默认取最高严重度；`stackSeverity=true` 时相加。规则写在受益状态上，因此所有来源使用同一规则。

```xml
<HediffDef>
  <defName>My_StackingSupport</defName>
  <label>协同后勤</label>
  <description>每点光环强度提供25%搬运容量和5公斤额外负重，最多3点。</description>
  <hediffClass>BANWlLib.Auras.Hediff_FriendlyAuraEffect</hediffClass>
  <isBad>false</isBad>
  <initialSeverity>1</initialSeverity>
  <maxSeverity>3</maxSeverity>
  <modExtensions>
    <li Class="BANWlLib.Auras.FriendlyAuraEffectExtension">
      <stackSeverity>true</stackSeverity>
      <maximumSeverity>3</maximumSeverity>
    </li>
  </modExtensions>
  <stages>
    <li>
      <multiplyStatChangesBySeverity>true</multiplyStatChangesBySeverity>
      <statOffsets>
        <BANW_HaulingCapacityMultiplier>0.25</BANW_HaulingCapacityMultiplier>
        <BANW_CarryMassOffset>5</BANW_CarryMassOffset>
      </statOffsets>
    </li>
  </stages>
</HediffDef>
```

将源的 `effectHediff` 改成 `My_StackingSupport`。两个强度均为 1 的源提供严重度 2，即 +50% 搬运容量和 +10 kg；第四个源不会超过严重度 3。

`FriendlyAuraEffectExtension` 的 `stackSeverity` 默认 false，`maximumSeverity` 默认 10。最终严重度同时受 `HediffDef/maxSeverity` 限制，取较小上限。

`multiplyStatChangesBySeverity=true` 时，属性加成随严重度变化；未启用时，普通 `statOffsets/statFactors` 按当前阶段的固定值生效。多个 `stages/li/minSeverity` 可用于配置阶梯效果。后勤光环默认使用固定加成。

受益状态的 `statOffsets` 也可以填写 `MoveSpeed` 等原版或模组属性。周期治疗、伤害和生成物品需要相应的状态组件。

## 5. 装备与武器特性配置搬运词条

服装和武器均在现有 `ThingDef` 中使用 `equippedStatOffsets`。如果已有节点，合并条目，不能重复建立同名节点。

```xml
<equippedStatOffsets>
  <CarryingCapacity>20</CarryingCapacity>
  <BANW_HaulingCapacityMultiplier>0.5</BANW_HaulingCapacityMultiplier>
  <BANW_CarryMassOffset>15</BANW_CarryMassOffset>
  <BANW_CarryMassMultiplier>0.25</BANW_CarryMassMultiplier>
</equippedStatOffsets>
```

这表示原版搬运容量固定 +20、搬运倍率 +0.5、质量负重 +15 kg、负重倍率 +0.25。角色穿戴或装备后才受益；只把装备放进背包不生效。`statBases` 表示物品自身属性，不等价于对穿戴者的加成。

原版武器特性 `WeaponTraitDef` 同样支持上面的 `equippedStatOffsets` 节点。它与小人特性 `TraitDef` 是两种定义，不要混用层级。

## 6. 小人特性配置

在 `TraitDef/degreeDatas/li` 中配置词条。以下片段放在现有 `TraitDef` 内：

```xml
<degreeDatas>
  <li>
    <degree>0</degree>
    <label>后勤专家</label>
    <description>擅长负重与搬运。</description>
    <statOffsets>
      <BANW_HaulingCapacityMultiplier>0.5</BANW_HaulingCapacityMultiplier>
      <BANW_CarryMassOffset>20</BANW_CarryMassOffset>
    </statOffsets>
    <statFactors>
      <BANW_CarryMassMultiplier>1.5</BANW_CarryMassMultiplier>
    </statFactors>
  </li>
</degreeDatas>
```

原有特性若有多个程度，就在需要生效的每个 `li` 中分别配置，保留原来的 degree。不同特性、装备和状态通过原版属性系统共同参与计算。

## 7. 普通状态配置

非光环状态照常使用 `HediffWithComps`，在 `stages/li` 中填入词条即可，不需要使用光环受益类。

```xml
<HediffDef>
  <defName>My_CarryBoost</defName>
  <label>搬运强化</label>
  <description>暂时提高单次搬运容量与质量负重。</description>
  <hediffClass>HediffWithComps</hediffClass>
  <isBad>false</isBad>
  <initialSeverity>1</initialSeverity>
  <comps>
    <li Class="HediffCompProperties_Disappears">
      <disappearsAfterTicks>3600</disappearsAfterTicks>
    </li>
  </comps>
  <stages>
    <li>
      <statOffsets>
        <BANW_CarryMassOffset>10</BANW_CarryMassOffset>
      </statOffsets>
      <statFactors>
        <BANW_HaulingCapacityMultiplier>2</BANW_HaulingCapacityMultiplier>
        <BANW_CarryMassMultiplier>1.2</BANW_CarryMassMultiplier>
      </statFactors>
    </li>
  </stages>
</HediffDef>
```

## 8. 计算规则与配置限制

- 倍率属性默认 1：`statOffsets` 写 0.5 表示加到 1.5；`statFactors` 写 1.5 表示乘 1.5。固定负重默认 0，直接增加公斤数使用 offsets。
- 单次搬运数量由 CarryingCapacity、搬运倍率、身体能力、物品单位体积和堆叠上限共同决定。角色仍须具备搬运工作能力。
- 若某物品原本最多堆叠 75，即使容量可容纳 150，也最多一次搬 75。未达堆叠上限的角色或高单位体积物品更容易看到容量提高的效果。
- 质量负重：`max(0, (基础承重 + BANW_CarryMassOffset) × BANW_CarryMassMultiplier)`。原版基础通常是体型 ×35 kg。
- 体型 1、固定 +15 kg、倍率 1.25 时，上限为 `(35+15)×1.25=62.5 kg`。负重词条影响背包和商队承重，不改变物品收集行为。
- 原版不能承担负重的角色不会因为词条变得有资格负重。装备本身的质量仍照常计入已用负重。
- 光环每 30 tick（0.5 游戏秒）统一检查：进入范围、离开范围、换阵营、源倒地或移除源，通常在下一次检查生效。范围不会跨地图、容器或商队。
- 暂停时不推进光环检查。受益状态由管理器续期，离图时会失效；返回地图后重新建立覆盖。
- 同名光环不会每轮重新添加状态；只有首次覆盖才创建，持续覆盖更新强度。不同受益 defName 可以同时存在。
- 受益状态不能继续挂光环发射组件，也不要配置让受益自行重命名、变换或添加其他光环源的逻辑。
- requiredTargetHediffs/excludedTargetHediffs 用于检查独立状态，不要把本光环受益或其他相互依赖的光环受益作为条件，以免形成循环依赖。
- 不要给受益状态配置 Disappears、SeverityPerDay 等自行消退组件；持续时间由源状态控制。普通有时限状态使用第7节的方式。
