## 延迟连射索引越界修复

### 异常表现

地图 Tick 处理延迟子弹时可能抛出：

```text
System.ArgumentOutOfRangeException: Index was out of range.
at BANWlLib.BattleSystem.MultiShotProjectileDelayComponent.FireDueProjectiles
```

### 根因

`FireDueProjectiles` 原本倒序遍历 `pendingProjectiles`。某发子弹返回 `CancelSequence` 后，代码会立即调用 `RemoveSequence`，一次删除同一序列的多个元素。外层循环仍继续使用删除前的索引，因此下一轮可能访问已经不存在的位置。

### 当前处理方式

- 扫描期间使用集合记录已取消的 `sequenceId`。
- 已取消序列的后续任务在当前扫描中直接移除，不再发射。
- 扫描结束后统一清理尚未到期或此前已经越过的同序列任务。
- 遍历期间不再执行会破坏外层索引的批量删除。

该处理保留“任意一发判定序列取消后，整轮剩余子弹全部取消”的原有规则。

## 连射音效配置

### 全局重复音效

`CompProperties_AbilityMultiShotProjectile` 新增：

```xml
<repeatShotSound>true</repeatShotSound>
```

规则如下：

- 字段不写时默认为 `false`，不会额外补播连射音效。
- 开启后复用当前能力 `verbProperties.soundCast`。
- 原版施法时播放的 `soundCast` 作为第一发音效。
- 从第二发开始，队列按照各发 `delayTicks` 补播相同音效。
- 开启后如果没有配置 `soundCast`，日志会直接输出配置错误。

示例：

```xml
<verbProperties>
  <soundCast>BANW_Wp_AR_At</soundCast>
</verbProperties>
<comps>
  <li Class="BANWlLib.BattleSystem.CompProperties_AbilityMultiShotProjectile">
    <projectileDef>BANC_Bullet_Example</projectileDef>
    <repeatShotSound>true</repeatShotSound>
    <shots>
      <li><delayTicks>0</delayTicks></li>
      <li><delayTicks>6</delayTicks></li>
      <li><delayTicks>12</delayTicks></li>
    </shots>
  </li>
</comps>
```

以上配置共播放三次射击音效：原版首发一次，6 Tick 和 12 Tick 各补播一次。

### 每发独立音效

`MultiShotProjectileShotConfig` 新增可选字段：

```xml
<soundDef>BANW_Shot_A</soundDef>
```

完整示例：

```xml
<verbProperties>
  <soundCast></soundCast>
</verbProperties>
<comps>
  <li Class="BANWlLib.BattleSystem.CompProperties_AbilityMultiShotProjectile">
    <projectileDef>BANC_Bullet_Example</projectileDef>
    <shots>
      <li>
        <delayTicks>0</delayTicks>
        <soundDef>BANW_Shot_A</soundDef>
      </li>
      <li>
        <delayTicks>6</delayTicks>
        <soundDef>BANW_Shot_B</soundDef>
      </li>
      <li>
        <delayTicks>12</delayTicks>
        <soundDef>BANW_Shot_C</soundDef>
      </li>
    </shots>
  </li>
</comps>
```

### 音效优先级

| 情况 | 实际音效 |
| --- | --- |
| 当前发配置了 `soundDef` | 播放当前发自己的 `soundDef` |
| 当前发未配置 `soundDef`，且是第二发或之后，同时开启 `repeatShotSound` | 播放 `verbProperties.soundCast` |
| 当前发未配置 `soundDef`，且未开启 `repeatShotSound` | 队列不额外播放音效 |
| 第一发未配置 `soundDef` | 由原版 Ability 施法流程播放 `soundCast` |

单发 `soundDef` 优先于全局重复音效。完全自定义每发音效时，应将 `verbProperties.soundCast` 留空，避免第一发同时播放原版施法音与单发音效。

音效只在该发投射物成功生成并发射后播放。目标失效、施法者状态不满足或序列取消时，不会播放对应发的音效。待发射任务会保存 `shotSoundDef`，存读档后仍能继续使用正确音效。

## 护盾唯一与刷新规则

### 当前规则

| 场景 | 处理结果 |
| --- | --- |
| 同一个护盾重复施加 | 新计算值覆盖当前剩余护盾量，并刷新持续时间 |
| 不同角色施加相同 HediffDef | 后一次护盾覆盖前一次护盾量，并刷新持续时间 |
| 不同角色施加不同 HediffDef | 移除旧战斗护盾，只保留后施加的护盾 |
| 新护盾数值低于旧护盾剩余值 | 仍使用新护盾数值，不取最大值，也不叠加 |

### 应用流程

`BattleStatUtility.ApplyShield` 当前按以下顺序处理：

1. 根据施法者最终治愈力和 `shieldPowerRatio` 计算本次护盾值。
2. 获取或创建请求指定的护盾 Hediff。
3. 验证 Hediff 包含 `HediffComp_BattleShield`。
4. 移除目标身上除当前 Hediff 外的其他战斗护盾。
5. 使用本次计算值刷新 `remainingShield`。
6. 添加新 Hediff，或重置现有 Hediff 的消失计时。

护盾吸收伤害的规则没有改变：护盾会完整抵消一次符合条件的敌方伤害，即使剩余护盾量低于该次伤害，随后护盾量降为零并移除。

### 玛丽护盾 Def 修正

玛丽技能原本定义了 `BANW_BattleShield_Mari`，但实际动作和预览错误引用了 `BANW_BattleShield_Yuuka`，导致玛丽使用优香的护盾持续时间。

当前配置已经统一为：

```xml
<shieldHediffDef>BANW_BattleShield_Mari</shieldHediffDef>
```

玛丽护盾现在使用自身定义的 1200 Tick，也就是 20 秒持续时间；预览配置和实际动作保持一致。

## 验收清单

### 连射队列

1. 使用带延迟的多发投射物技能攻击有效目标。
2. 在连射期间移动施法者、击晕施法者或让目标失效，触发 `CancelSequence`。
3. 确认剩余子弹停止发射，日志中不再出现 `ArgumentOutOfRangeException`。
4. 在延迟连射期间存档并读档，确认队列可以继续执行。

### 连射音效

1. 不配置 `repeatShotSound`，确认没有额外补播音效。
2. 配置 `repeatShotSound=true` 和有效 `soundCast`，确认音效总次数与 `shots` 数量一致。
3. 为每发配置不同 `soundDef`，确认音效按 `delayTicks` 和配置顺序播放。
4. 混合使用全局音效和单发音效，确认单发 `soundDef` 覆盖当前发的全局音效。
5. 取消连射序列，确认未发射子弹不会提前播放音效。

### 护盾

1. 对同一目标连续施加同一个护盾，确认护盾值被新值覆盖而不是相加。
2. 先施加高值护盾，再施加低值护盾，确认最终显示低值护盾。
3. 依次使用玛丽、优香和望的护盾，确认健康面板同时只保留一个战斗护盾。
4. 确认后施加护盾的持续时间重新开始计算。
5. 确认玛丽护盾持续 20 秒，并使用 `BANW_BattleShield_Mari`。
